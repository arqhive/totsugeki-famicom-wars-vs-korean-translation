# 기술 문서

일본판 `RBWJ01`(Kuju Entertainment 엔진, 1편과 같은 계열) 기준입니다. 디스크 안 파일 대부분은 압축되어 있지 않고, 레벨 리소스(`.res.gz`)와 시작 화면 텍스처(`.btf.gz`)만 gzip입니다.

## 디스크

- DATA 파티션 하나(파티션 오프셋 `0xF800000`)의 표준 Wii 디스크입니다. 파일 7,274개, 크기 합 약 2.4GB가 데이터 공간 약 4.0GB에 흩어져 있어 파일 사이에 빈틈이 많습니다.
- `inplace.py`는 원본 ISO의 배치를 그대로 두고 바뀐 파일만 교체합니다. 원본 크기 이하인 파일은 원래 자리에 쓰고, 커진 파일(문자열 일부, 다시 압축한 `.res.gz`)은 빈틈으로 옮긴 뒤 FST의 위치·크기를 고칩니다.
- 바뀐 2MB 그룹의 H0/H1/H2 해시를 직접 계산하고 wit로 암호화한 뒤, 원본 ISO에 그 그룹만 옮겨 H3 표와 TMD를 갱신하고 가짜 서명합니다. 그래서 배포 xdelta에는 바뀐 그룹만 들어갑니다.
- 다만 ISO 통째 xdelta는 특정 원본 ISO 하나에만 맞습니다. WBFS는 쓰지 않는 영역(정크 데이터)을 버리고, ISO로 되돌릴 때 도구마다 그 자리를 다르게 채우므로 같은 게임도 MD5가 달라집니다. 그래서 v0.1.1부터는 파일 단위 패처로 배포합니다.

## 파일 단위 패처 `make_patcher.py` + `patcher/`

- 빌드 결과에서 원본과 다른 파일 199개마다 xdelta 차분을 만들고, `data/manifest.txt`에 모드·차분 파일·경로·원본 MD5·결과 MD5를 적습니다.
- `.res.gz` 등 gzip 파일 11개는 압축을 푼 내용끼리 차분합니다. 로고 하나만 바뀌어도 압축 결과 전체가 달라지기 때문입니다(파일 그대로 차분하면 약 85MB, 풀어서 차분하면 0.2MB). 패처가 적용 후 PowerShell `GZipStream`으로 다시 압축하며, 게임은 풀어서 읽기만 하므로 압축 바이트가 달라도 됩니다.
- 패처(`patch.ps1`)는 `wit extract --psel data --pmode none`으로 DATA 파티션을 풀고, 차분을 적용한 뒤 `wit copy`로 ISO나 WBFS를 새로 조립합니다. 결과에는 UPDATE 파티션이 빠집니다.
- cygwin판 wit은 `LANG=en_US.UTF-8`이 없으면 한글이 들어간 경로를 열지 못합니다(`C.UTF-8`도 실패). wit.exe에는 `cygwin1`, `cygz`, `cygcrypto-1.1`, `cygncursesw-10` DLL이 필요합니다.

## 문자열 `Data/Strings/*.str`

1편과 같은 형식입니다(리틀 엔디언, magic `0x0005A177`, 항목 0x38바이트, 본문 u16 배열).

- 일본판 디스크에는 7개 언어 파일이 모두 들어 있습니다. 게임은 `*Japanese.str`(70개)과 `globjap.str`을 읽습니다.
- 일본어는 문자 코드가 아니라 **글자 번호**입니다. 상위 바이트 `0xB0`+시트, 하위 바이트 `0x40`+칸(0에서 120까지)이고, 줄바꿈은 `0x0A`입니다. 상위 바이트가 0이면 ASCII 칸(코드−0x20)입니다.
- 실행 코드(`0x8031D08C` 등 세 곳)가 `(상위−0xB0)×121+(하위−0x40)`로 칸을 구합니다. 시트 번호를 막는 검사는 없어서 원본보다 시트가 많은 폰트(10장까지 확인)도 정상 출력됩니다.
- 미션 대사 항목에는 음성 ID(예: `SP_0.1_SE_QALEN_001`)가 있어 화자를 알 수 있습니다. 영상 자막은 첫 줄이 빈칸(화자 자리)이고 화자 정보가 없습니다.

## 폰트 `Data/font/<장면>.btf` + `.wdf`

- `.btf`: `FTBG` 헤더와 `DXTG` 청크(256×256, C4, RGB5A3 16색 팔레트) 여러 장입니다. 1편의 `FTBX`/`TXET`와 구조가 조금 다릅니다(`btfg.py`).
- 칸은 22×22 격자이고 시트당 11×11=121칸입니다. `.wdf`는 칸마다 글자 폭 1바이트이며, 길이가 곧 글자 수입니다.
- 첫 시트(ASCII)와 둘째·셋째 시트의 팔레트가 서로 다릅니다. 새 시트를 붙일 때는 마지막 시트 팔레트를 복사하고, 다른 시트에 글자를 넣을 때는 가장 가까운 팔레트 번호로 바꿉니다.
- 미션·메뉴·도감 폰트는 칸 0에서 95까지 ASCII, 그다음 공통 문자열(`globjap.str`) 글자, 그 뒤 장면 글자 순서입니다. 공통 글자는 모든 폰트에서 같은 칸이어야 합니다. 영상 자막 폰트는 ASCII 뒤에 자막 글자만 있습니다.

### 게임의 글자 그리기에서 확인한 점

- 게임은 **글자 폭(wdf)만큼 칸을 잘라 그립니다.** 폭을 칸 크기(22)보다 크게 하면 옆 칸 글자가 양옆으로 딸려 나옵니다.
- 칸의 오른쪽·아래 끝에서 **옆 칸의 0열, 아래 칸의 0행을 섞어 읽습니다.** 그래서 모든 글자 칸은 0행·0열을 비웁니다.
- 글자 간격 = 폭 + 자간(전역값 + 폰트값 − 1.0)입니다. 자간 계산 세 곳(`0x8031D06C`, `0x8031D130`, `0x8031EA4C`)은 공용 상수 1.0을 읽습니다. `patch_dol.py`에는 −1.0을 가리키게 바꿔 자간을 +2 하는 패치가 있지만 v0.1에서는 쓰지 않습니다.
- 줄 간격 = 폰트 로드 때 저장하는 줄 높이(시트 칸 높이의 최댓값) × 배율 + 전역값입니다. `patch_dol.py`에는 `0x8031C48C`부터 다섯 명령을 고쳐 줄 높이를 칸 높이+3으로 저장하는 패치(행간 +3px, 환경 변수 `BW2_LINE_PATCH=1`)도 있습니다. v0.1은 원본 행간을 씁니다. 줄 높이는 줄바꿈 위치 계산에만 쓰입니다.

## 한글 글자 `korglyph.py`

- 1편 한글 패치와 같은 방식입니다. 맑은 고딕 17px를 4배 해상도에서 그리고, 흰 채움, 둥근 1px 검은 테두리, 아래로 2px 내린 그림자를 합성한 뒤 원본 16색 팔레트로 줄입니다.
- 1편과 달리 글자마다 잉크 왼끝을 2열에 맞춰 0열을 비웁니다(`ㅇ`으로 시작하는 글자도 잘리지 않음). 흰 채움 폭은 16px 이하로 눌러 넣고, 글자 간격은 19px입니다.
- `「」 … ★ ♪`와 가나, 악센트 문자는 원본 일본어 폰트의 같은 글자 그림을 옮겨 씁니다.
- 시험 과정에서 확인한 점: 픽셀 글꼴(갈무리11)을 크게 그리면 `ㅏ`의 1픽셀 가로획과 사선이 테두리에 묻혀 점처럼 보였습니다. 테두리 없이 그리면 옆 칸이 섞여 보이고 획이 가늘어 보였습니다.

## 원문 판독

일본어 원문이 글자 번호뿐이라 폰트 그림을 읽어 복원합니다. 결과는 `tools/data/labels.json`({폰트: {칸: 글자}}, 15,273칸)입니다.

- 1편 판독표와 흰 채움 모양(밝기 180 이상)이 픽셀까지 같은 칸은 그 글자로 정했습니다. 2편 폰트끼리 모양이 같은 칸에도 전파했습니다.
- 나머지 약 680개 모양은 검수 시트로 직접 판독했습니다. 1편 판독표에서 온 글자 1,085개도 전수 대조해 1편 판독 오류 14건(説·脱, 達·連, 関·開, 特·持, 闇·聞, 賭·諸, 昔·首, 因·囚, 작은 가나)을 바로잡았습니다.
- 모양이 같은 가타카나와 한자·히라가나(エ·工, オ·才, ロ·口, ー·一, ヘ·へ 등)는 `jpdec.py`가 앞뒤 글자로 정합니다.

## 그림 글씨

일본판과 북미판의 모든 리소스 텍스처를 비교해, 일본판에만 있는 글자 그림 13장을 찾았습니다.

| 그림 | 위치 | 형식 |
|---|---|---|
| 타이틀 로고 `BWii_logo` | `Frontend2`, `credits`, `fe_*` 레벨 리소스 9곳 | P8(C8, RGB5A3 256색) |
| 뒤로 버튼 `but_back_n`, `but_back_s` | 같은 9곳 | P8, RGBA8 |
| 작은 로고 `BWii_logo_mini` | `Frontend2` 리소스, `Loading/ObjButton_logo.btf` | CMPR, RGBA8 |
| 로딩 로고 `BWii_logo_load2` | `Loading/Backdrop.btf` | RGBA8 |
| 스트랩 경고 `strapA`, `strapB` | `Startup/strap_*_jp.btf.gz`(4:3, 16:9) | CMPR |
| 세이브 데이터 로고 | `Loading/BWii_logo.tpl` | RGB5A3 |
| 채널 배너·아이콘 로고 | `opening.bnr`의 `banner.bin`, `icon.bin` | RGB5A3 |

- `texenc.py`가 형식별로 인코딩합니다. `opening.bnr`은 `bnrpack.py`가 안쪽 U8을 풀어 그림을 바꾸고 LZ77로 다시 압축한 뒤 IMD5 해시와 바깥 U8을 고칩니다. IMET 헤더의 크기는 압축을 푼 크기라 그대로 둡니다.
- 승리·패배 연출 글자(VICTORY, DEFEAT)는 일본판부터 영문입니다. 포대 텍스처의 낙서 무늬는 북미판에도 같은 그림이라 번역 대상이 아닙니다.
